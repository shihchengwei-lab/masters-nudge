## 讀取與回覆邊界補驗（2026-09-18）

依 reliability 檢查輸入失敗與已發生的送出動作；依 simplicity 保留單一回覆，不加重試、強制讀檔或新的沉默種類。evolve 檢查後，改動仍留在原有讀取服務、接入層及測試程式，SPEC 未變更。

- 讀檔行號型別錯誤：先重現字串／空值行號造成未記錄的例外，再改成先檢查行號。測試已執行並通過，四個錯誤呼叫均有故障紀錄，後續合法讀取仍可用。
- 紀錄目錄無法建立：先重現錯誤日誌也寫不下時沒有故障回覆，再讓日誌失敗寫到標準錯誤。測試已執行並通過；這只涵蓋路徑被檔案占用，不代表所有磁碟故障都測過。
- 讀取服務是 Provider 的必要依賴：設為 `required=true`，使用 Codex 內建的啟動限制。依 [官方文件](https://learn.chatgpt.com/docs/extend/mcp)，選用服務可能在初次工具清單形成前尚未就緒；必要服務會等待自身啟動期限。設定測試已通過；沒有證據說這就是歷史沉默的原因。
- 送出後才寫交付紀錄：先重現資料庫錯誤導致兩份互相矛盾的 JSON，再把送出後的紀錄錯誤留在錯誤日誌。正式使用不追加第二份回覆；實測仍以非零結束碼標記無效。兩種模式的測試已執行並通過；沒有宣稱磁碟故障已消失，或接收端一定讀到了已寫出的文字。
