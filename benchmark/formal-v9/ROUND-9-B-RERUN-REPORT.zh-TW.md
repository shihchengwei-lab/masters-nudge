新 B 相對 A 多 **5,102.015 秒（54.7%）**、**2,434,548 非快取輸入 token（121.4%）**。相對上一版 B 少 **607.253 秒（4.0%）**，但多 **137,549 非快取輸入 token（3.2%）**。新 B 的 Provider 單獨使用 1,930,641 非快取輸入 token；有效題目中有 60 次回饋、66 次沉默。回饋變多不是品質目標，這次也沒有換來更高完成率。

這些案例顯示本次縮寫提高了回饋數，也產生了有效的結構線索；同時有錯誤方向和該回饋卻沉默的案例。唯一套件差異是 Buddy prompt，但每臂由模型獨立生成，不能把總分差額直接歸因於單一句規則。下一個候選應在固定相同 Provider 中途材料下，檢查「任務目標可達、既有 API 行為及輸入值域保持」是否先於結構負擔排序，再用 Actor 延續和完整 B 臂驗證；未驗證前不把這個候選宣告為產品改善。

Vue-11694 的 `isReactive(reactive(ref(1)))` 斷言是交卷後套入的預留測試新增內容，並非起點已提交的既有測試；上版報告稱它為「非隱藏要求」是錯誤的。新 B1 的 Provider 提出 `reactive(ref) = ref`，與該預留斷言方向相反，但不能把未見的斷言當作它漏讀的證據。事後以還原的中途補丁重播，上一版已提交的 Buddy prompt 提出「ref 寫入有兩條觸發路徑，應由 ref 的依賴負責」；此結果只驗證當下回饋方向，沒有取代完整 B 臂成績。正式完成率仍依封存預留測試計算；題目與該斷言的對齊缺口須在後續解讀中明列。
